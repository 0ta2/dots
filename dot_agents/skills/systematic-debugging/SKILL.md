# Systematic Debugging

症状に対処する前に、再現と証拠から原因を特定する。

## 1. 再現する

1. エラー、警告、stack trace、終了コードを省略せず読む。
2. 最小の再現手順と期待結果・実際の結果を記録する。
3. 同じ条件で再現するか確認する。再現しない場合は追加データを集める。
4. 直近のコード、設定、依存関係、環境の変更を確認する。

## 2. 仮説を立てる

データの流れを障害箇所から入力側へたどり、値が最初に壊れる場所を探す。
複数コンポーネントがある場合は、境界ごとに入力・出力・設定の伝播を観測する。
同じコードベースにある正常な実装と比較し、差分を列挙する。

証拠から「X が原因だと考える。根拠は Y」と 1 つの仮説に絞る。
理解できていない点は明示し、修正案で埋めない。

## 3. 最小の切り分けをする

1. 仮説を否定または確認できる最小の観測・実験を選ぶ。
2. 一度に 1 変数だけ変える。
3. 結果が仮説と一致するか確認する。
4. 一致しなければ変更を積み重ねず、証拠を更新して新しい仮説を立てる。

## 4. 修正する

1. 可能なら最小の再現を回帰テストにする。
2. 症状ではなく、確認した原因を直す最小の変更を加える。
3. 関係のないリファクタや複数の修正を混ぜない。
4. 回帰テスト、関連テスト、元の再現手順を実行する。

修正が失敗したら再現と仮説へ戻る。同じ問題で修正が繰り返し失敗する場合は、
追加修正を重ねず、設計上の問題かどうかを整理してユーザーへ報告する。

## 完了条件

- 元の問題を同じ手順で再現できなくなった
- 原因を説明できる
- 回帰テストが修正前に失敗し、修正後に通る
- 関連テストに新しい失敗がない
