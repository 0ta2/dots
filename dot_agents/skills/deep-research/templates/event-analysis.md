# イベント分析モード (--event) の型

「会社の価値が一気に上下動するイベント発生 → 高速に波及を分析する」用途の
サブクエリ分解と章立て。キャップ・エージェント数などの実行条件は SKILL.md 側の定義に従う。

> **外部依存: kabu-lab リポジトリ** (`~/ghq/github.com/0ta2/kabu-lab`)。
> このモードだけが harness の外に書き込む (`events.jsonl` への仮想記録)。
> 従うルールの正本は kabu-lab の CLAUDE.md (投資助言にしない・既存行の変更禁止)。
> kabu-lab が無い / 未結線の環境では記録をスキップしてレポート納品のみ行う (末尾参照)。

## 前提

- 出力は**判断材料の整理**であり投資助言ではない。「買え/売れ」の指示・執行はしない
  (kabu-lab CLAUDE.md の憲法と同じ)。売買判断はユーザー
- 波及先候補には必ず**否定材料**と**確度**を付ける。書けない候補は出さない

## サブクエリ分解 (5方向固定)

1. **イベントの事実確認** — 一次情報 (適時開示・公式IR・当局発表) で何が起きたかを確定する。
   憶測記事と一次情報を区別する
2. **直接の当事者** — 対象企業とその財務・株主構成への直接影響
3. **波及先: 資本・取引関係** — 株主構成 (持ち合い・大株主)、取引先、提携先で
   価値が動きうる上場企業
4. **波及先: 同業・類似ポジション** — 「次に同じことが起きる」と連想される同業銘柄
5. **過去の類似イベント** — 同型イベントで関連銘柄の株価がどう反応したか (数日〜数週間)。
   反応しなかった事例も探す (生存バイアス対策)

## レポートの追加章立て

report_template.html の「根拠」を以下の h3 構成にする:

- イベントの事実 (一次情報ベース)
- 波及先候補 (表形式: 銘柄/コード・波及経路・想定方向・根拠・否定材料・確度)
- 過去の類似イベントの反応 (反応しなかった事例を含める)

「反証・リスク」には最低限「この連想が既に株価に織り込み済みの可能性」を必ず検討する。

## kabu-lab への仮想記録 (勝率実測)

レポート納品後、kabu-lab の `events.jsonl` に波及先候補を 1 行ずつ追記する
(実弾投入の判断はユーザー。この記録は後日の答合せ用):

```json
{"date": "YYYY-MM-DD", "event": "イベント1行", "code": "銘柄コード", "name": "銘柄名", "direction": "up|down", "path": "波及経路1行", "confidence": "high|mid|low", "price_at_call": 終値, "verify_after_days": 5}
```

記録先ファイルが無い場合は kabu-lab 側の結線が未完了。レポートに
「仮想記録はスキップした (events.jsonl 未整備)」と明記して納品は完了させる。
