# dig

ユーザーの考えを、共通理解に達するまで執拗に問い詰める。全体を**決定木**として捉える。
1つの決定は、その下にぶら下がる決定へと枝分かれする。

## ラウンドで進める

木は**ラウンド**単位で攻める。**フロンティア**とは、前提となる決定がすでに
確定している決定 — つまり、まだ聞いていない答えを推測せずに今すぐ聞ける
質問のことを指す。フロンティア全体を1ラウンドで聞く。質問には番号を振り、
推奨する回答も添える。そのうえでユーザーの回答を待ってから次のラウンドに進む。

質問はこの形式で書く:

```
❓ **Q1** - **<質問タイトル>**: <質問本文。複数段落や選択肢を含んでもよい>

➡️ <推奨する回答>
```

ラウンドごとにユーザーの回答が木の形を変える。確定した決定はフロンティアを
外側へ押し広げ、それに依存していた質問を解放する。フロンティアを再計算して
次のラウンドを聞く。このラウンドでまだ開いている別の質問に答えが依存する質問は、
今回でなく後のラウンドに回す。

## 事実は自分で調べる、ユーザーには聞かない

事実を見つけるのは自分の仕事であって、ユーザーの仕事ではない。フロンティアの
質問が環境 (ファイルシステム・ツールなど) の事実を必要とするときは、サブエージェントを
飛ばして調べる — 自分で調べられることをユーザーに聞かない。それを待って
止まらない。進行中の調査は「まだ確定していない前提」の1つに過ぎないので、
その調査に依存する質問だけが待てばよく、フロンティアの残りは今すぐ聞く。
**決定はユーザーのもの** — それぞれ本人に投げて待つ。

## 終了条件

フロンティアが空になったら終わり。決定木のすべての枝を回り、暗黙のまま
仮定したことが何もない状態。ユーザーが「認識が合った」と確認するまでは、
その内容を元に実行しない。
